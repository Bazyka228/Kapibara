# Second Project — правила команды ИИ-агентов

## Проект и рабочие каталоги

- Это существующая Unity 2D/uGUI игра для Яндекс Игр. HTML5-доставка означает Unity WebGL; не переписывать её на другой движок без отдельного запроса.
- Рабочий Unity-проект: `C:/Users/fedor/Second Project`, Unity `6000.6.5f1`, сцена `Assets/Capybara67/Scenes/Capybara67_Idle.unity`.
- Пространство разработки: `C:/Users/fedor/OneDrive/Документы/ChatGPT/Second Project`. `CurrentProject/` — зеркало исходников, а не самостоятельный полный Unity-проект. `UnityContent/` и `LegacyArchive/` — история, не источник актуального кода.
- Начать с `.codex/README.md` и `CurrentProject/Design/AgentTeam.md` в пространстве разработки либо `Design/AgentTeam.md` в рабочем Unity-проекте. Исторические документы сверять с текущим кодом и свежими отчётами.
- Если пути или версия изменились, сначала найти актуальный проект. Не создавать новый проект поверх существующего и не перетирать более свежие файлы зеркалом.

## Делегирование и владение файлами

- Делегировать независимые существенные задачи специализированным субагентам. Использовать роли из `.codex/agents/`: game-designer, gameplay-programmer, ui-ux-designer, game-artist, animation-specialist, qa-game-tester, economy-balancer, yandex-games-specialist.
- Ведущий агент координирует зависимости, интеграцию и итоговую проверку. До трёх субагентов одновременно, если лимит сессии позволяет. Восемь ролей не означают восемь постоянно работающих процессов.
- Каждое поручение содержит цель, разрешённые файлы, запреты, критерии приёмки и требуемые проверки. Не выдавать один файл двум пишущим агентам. Анализ можно выполнять параллельно с независимыми правками.
- Shared partial class `CapyIdleGame`, `IdleModel`, каталоги, общие Shape/Contour и проверочные скрипты требуют одного владельца на время изменения. Новый partial-файл тоже может конфликтовать по состоянию и именам методов.
- Субагент возвращает изменённые пути, результат, реально выполненные проверки, риски и необходимые действия интегратора. Не отменять чужие изменения, не делать массовый reset/clean.
- Только назначенный интегратор переносит изменения в рабочий Unity, управляет редактором, запускает общий прогон и сборку. Только один агент владеет окном/браузерным профилем в данный момент.

## Защищённая графика

- Актуальное направление: прежний простой мультяшный стиль. Допустимы небольшие детали; не возвращать глянцевые материалы, растровые замены декора или объёмные UI-иконки без нового запроса пользователя.

- Не менять дизайн, цвета, пропорции, спрайты капибар и внешний вид нарядов без отдельного запроса пользователя.
- Защищены `Resources/Characters`, `Resources/Outfits`, `Resources/CompleteSets`, `Resources/Accessories`, маски окрасов, eye shader, портреты и код сборки персонажа. Не обходить запрет через общий материал, шейдер, импорт или родительский transform.
- Сохранять границу `CapyUnifiedGarden.protectedArtDepth`. Новые декор и UI должны соответствовать текущему стилю; не заменять существующую сцену или её композицию без задачи.
- Сохранять `.meta`/GUID. Перед изменением общих визуальных помощников зафиксировать хеши защищённых ресурсов, после — проверить их и кадры пяти возрастов с нарядами.

## Механики, экономика и сохранения

- Сохранять ключ `capy67.idle.v1`, резервный `.backup` и поддержку legacy-ключей. Добавлять поля с безопасными defaults; миграции должны быть идемпотентны.
- Не переименовывать и не удалять ID предметов, стадий, наград и покупок без миграции. Учитывать, что `IdleModel.Repair()` очищает неизвестные ID. Не повышать save version без обновления загрузчика и теста старых сохранений.
- Для изменения механики проверять старый профиль, повторную загрузку, повторную миграцию, дублирование выдачи награды и сохранение купленных предметов.
- Тесты работают только с отдельным `.validation`-профилем/изолированным браузером. Нельзя сбрасывать PlayerPrefs, подставлять тестовые монеты в профиль игрока или трогать его реальные покупки.
- Детская аудитория: короткие понятные действия и подсказки, честная стоимость и шанс награды, без ложной срочности. Числа удержания/дохода без измерений обозначать гипотезами. Награда за рекламу — только по подтверждённому callback.

## Интеграция и проверка

- После изменений выполнять проверки, соответствующие изменённой области; матрица и точные команды — в `Design/AgentTeam.md` / `CurrentProject/Design/AgentTeam.md`.
- Не переносить исходники/ресурсы и не менять тестовый код, пока Unity-прогон имеет статус RUNNING. Дождаться finally-восстановления профиля. Перед переносом сравнить зеркало с рабочими файлами и сделать резервную копию изменяемого набора.
- Компиляция не заменяет проверку рендеринга. Для UI, декора, ввода и анимаций проверять 320×568, 360×640, 390×844, 412×915 и изменение размера desktop; сохранять кадры, проверять читаемость, границы окон, касания, drag и паузу. Перечислять только реально проверенные разрешения.
- Не выдавать Unity Game View за браузер или физический Android. Для WebGL нужны свежая сборка, browser console/network, touch, background/resume, audio, reload/save и SDK-проверки.
- WebGL-сборка и публикация ранее приостановлены пользователем. Настройка команды не отменяет паузу. Готовить проверку можно, возобновлять сборку/публикацию — по новому запросу.
- Хранить датированные отчёты в `Verification/<задача>/`: команда, версия исходников/хеши, результаты, разрешения, кадры и ограничения. FAIL/BLOCKED/SKIPPED не заменять старым PASS. После успешных проверок не повторять всё без причины.

## Инструменты и зависимости

- Сначала использовать имеющиеся skills/MCP. Читать подходящий SKILL.md перед применением. Доступность инструмента проверять в текущей сессии, не считать наличие папки установкой или подключением.
- Game Studio установлен. Использовать `game-playtest` для браузерного QA, `game-ui-frontend` как ориентир визуальной иерархии, `sprite-pipeline` только для разрешённого декоративного арта. Его defaults Phaser/DOM/CSS/Three.js не применять к существующему Unity/uGUI: стек, сохранения и защищённая графика определены пользователем. Не добавлять второй движок или DOM-слой ради рекомендаций skill.
- Перед сторонней зависимостью проверить официальный источник/владельца, назначение, лицензию, точную версию, install scripts, сетевые обращения, права и необходимость. Зафиксировать результат; не запускать непроверенные bootstrap-скрипты и плавающий latest.
- Не устанавливать плагины по одному названию. Не менять глобальные разрешения, модель или MCP-настройки пользователя ради проектной задачи.
- Не добавлять в отчёты токены, cookies, полные профили или секретные настройки. Для браузерных тестов использовать отдельный контекст, для локального сервера — loopback.
- Общаться по-русски. Итог: что изменено, что проверено, что осталось непроверенным; без обещаний удержания, производительности или готовности к публикации без доказательств.
